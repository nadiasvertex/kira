# 67. LLVM and Ahead-of-Time Compilation

**Status:** Implemented

How the reference compiler produces native code: HIR is lowered to LLVM IR, optimized, emitted as an object file, and linked with Cinder's runtime support library into a standalone executable.

## Code generation

`src/llvm_codegen/storage_codegen.cpp` lowers the HIR storage form the bytecode compiler reads (chapter 62) into an `llvm::Module`. It reads types from the checker's type table and never re-infers.

- **Values.** Scalars are LLVM scalars; `int128`/`uint128` are `i128`. Every other value is inline bytes laid out by `src/runtime/value_layout.h`, the same layouts the VM uses.
- **Calls.** Direct calls name the instance's symbol. Closures and function values use indirect calls. A call that the HIR pass marked as a tail call becomes `musttail` when LLVM's preconditions provably hold and an ordinary call otherwise ([Tail-Call Optimization](../03-advanced/39-tail-call-optimization.md)).
- **Generators.** A `generator def` compiles to a small constructor that builds the generator's state block, plus a step function that resumes from the last `yield`. The state block holds the locals that the HIR pass found live across a `yield`. Both backends share one coroutine object of eight 8-byte slots: step function, state pointer, resume index, status, the scheduler's record, the last yielded value (two slots), and the state block's size (`src/runtime/coroutine.h`). The step function returns the new status (suspended, done or pending) and writes a yielded item to the value slot; `.next()` call sites read the status and build `some(value)` or `none` themselves.
- **Tasks.** An `async def` compiles like a generator that yields its result once. Inside a task, `await` is a suspension point: the code calls `cinder_rt_task_await_poll`, and if the awaited task has not finished it stores the resume index and returns `pending`. The step function resumes at the same `await` once the scheduler wakes it. In an ordinary function (the entry `async def main`) `await` calls `cinder_rt_task_block_on` and blocks the calling thread. Dropping a task asks the scheduler to cancel it first (`cinder_rt_task_cancel`), because a task the scheduler owns may be running on another thread. Every local of a step function, temporaries included, lives at a fixed offset in the state block, so a suspension saves and restores nothing and a pointer to a local stays valid across it. See [The Task Scheduler](69-task-scheduler.md).
- **Panics.** Checked arithmetic and other failing operations call a runtime panic function with a reason from the same closed set the VM uses, followed by `unreachable`.
- **Intrinsics.** The small set of primitive operations the standard library is written over (allocation, string scalar decoding, platform queries, I/O) become calls into the runtime library.
- **Fails closed.** A HIR construct the backend cannot lower is reported with its source location, never miscompiled.

## Optimization

At `-O0`, the default, the emitted IR is not optimized. `-O1`, `-O2` and `-O3` run LLVM's standard per-module pipeline at that level (bare `-O` means `-O1`). HIR inlining has already run before code generation at every level.

## Producing an executable

`cinder --compile FILE` takes these steps (`src/driver/aot.cpp`, `src/llvm_codegen/aot.cpp`):

1. Lower every reachable module to LLVM IR.
2. Synthesize a C-ABI `int main(void)` that calls the program's entry function and turns its result into an exit code: `unit` is 0, and an integer or `bool` is converted to `int`.
3. Optimize at the requested level and emit a native object file for the host target.
4. Link the object with the system C++ driver (with `-pthread`, for the scheduler's worker threads) against Cinder's runtime support archives: panic handling, the heap allocator, string operations, and the libraries these depend on.

The resulting executable has no dependency on LLVM.

## Storage-form details

Every slot is an entry-block byte `alloca` of its layout size and alignment, so aggregates are inline bytes and no heap allocation is emitted; SROA turns slots nothing takes the address of back into registers. Scalars load and store at their own width, and aggregates move with `memmove`. `p[i]` on a raw pointer is a byte `getelementptr` of the index times the element size. A function's signature starts with the hidden result address when the result is an aggregate or descriptor, followed by each non-zero-sized parameter; aggregate parameters are passed by address. An access claims the alignment its slot base and offset guarantee, packed projections are accessed unaligned, and anything reached through a loaded address uses alignment 1. Checked arithmetic, casts, literals, and panics come from `scalar_ops.{h,cpp}`. With `storage_codegen_options::entry_thunks`, each function also gets `__cinder_entry_<name>(const uint64_t *args, void *result)` so the JIT test helper (`jit_module::run_storage`) needs no per-signature call shape. A call to a runtime intrinsic is checked with `hir::check_intrinsic_signature` and declared on first use: an intrinsic that returns an aggregate or `str` calls `cinder_<name>_into(dest, args...)` and returns `void`, and any other calls `cinder_<name>` with the wire kinds in `src/intrinsics.h`, converting scalars to and from those widths. `test_variant` loads the sum's `i64` tag at `tag_offset` and compares it with the variant's tag by `icmp eq`, then stores the flag as a `bool`. A `fn` value is three words `{entry, env, glue}`: a function address, the environment block (null when nothing is captured), and a drop-glue address (null only when the environment is empty, since any block needs the glue to free it). A closure body or glue takes the environment as a leading `ptr` parameter. `make_closure` allocates the block with `cinder_rt_alloc` (nothing, when the environment is empty, as for a named function used as a value), stores each capture at its offset, and stores the three words; a call through a `fn` value loads the entry and environment and calls through the pointer with the environment first; `drop_in_place` of a `fn` value branches on a non-null glue and calls it; `release_environment` calls `cinder_rt_free` with the block and its size. Closure bodies and glue get no `__cinder_entry_` thunk, because they are reached only through a `fn` value. A generator is the same eight-word object. `make_generator` allocates the state block and the object with `cinder_rt_alloc` and stores the step's address, the state pointer, the resume index, the status, and the block size. A step's `coroutine_frame` slots are `getelementptr`s off the environment pointer, computed in the entry block; `dispatch` is a `switch` on the resume index straight after them, with one block per suspension point, and `suspend` stores the item address and resume index, returns `suspended`, and continues in its resume block. `resume` calls the step through the object's function pointer only when the status is suspended and otherwise reads the status back. `drop_in_place` of a generator hands a suspended one to `cinder_rt_task_drop`, resumes it inline with a cancel request when the scheduler does not own it, and calls `cinder_rt_task_release`. A task is the same object. `await #k` branches to the point's resume block when entered by dispatch; on the straight-line path it stores the resume index, calls `cinder_rt_task_await_poll`, and branches on the result: a false result returns `pending` from an `await.pending` block, and a true one continues in `await.ready`. In an ordinary function a task is read with `cinder_rt_task_block_on` followed by `take`. A group wait (`await all`/`await any`, and `block_on_group` outside a step) passes the pointer to the tuple of handles, which the runtime reads in place, and the member count to `cinder_rt_task_await_all_poll`/`cinder_rt_task_await_any_poll` (after the coroutine) or `cinder_rt_task_block_on_all`/`cinder_rt_task_block_on_any`. A crew wait passes the crew handle to `cinder_rt_crew_join_poll` (after the coroutine). `has_item` loads the value word and compares it with zero; `take` stores zero there after loading the item address, except a shallow `take` (a `read` of a `copy` result), which leaves the word set. A `string_literal` is a private global holding the bytes (`CreateGlobalString`) and two stores, the length and the global's address, into the descriptor. A descriptor's `length` and `data` places are its bytes at offsets 0 and 8. `checked_index` and `checked_end` are an unsigned compare (`uge` or `ugt`) and a `guard_panic` with `index_out_of_bounds`; the result is the checked value. A `check` is a `guard_panic` on the negated condition with the contract's reason. That reason is fatal, so a host that wants it back as an error, such as the storage tests, opens a `hosted_panic_scope`. `replicate` doubles the written prefix of the array with `memcpy` at constant offsets. `compile_storage_module` takes a program of storage modules, the entry module first, and declares every function of every module in one `llvm::Module` before any body: an entry-module function keeps its name as its symbol, any other module's is `module::name` (`hir::program_function_name`), and its entry thunk is named after that symbol; a call into another module is a direct call to the declared function. Each static is an internal global of zeroed bytes at its type's alignment, and a `global` slot is that global's address. One internal constructor calls each module's `static init` in module order and is registered in `llvm.global_ctors`, so the JIT runs it when it loads the module (`jit_module::create`) and an executable before `main`. It refuses by name `drop_in_place` of anything but a `fn` value, a generator, or a task, and 128-bit floats; `int128` and `uint128` are `i128`. `src/codegen_stress_test.cpp` compiles each corpus program through this compiler too and runs it in the JIT against the file's expected answer; a program whose answer is a panic is compiled but not run, since a panic ends the JIT's process. A call marked `tail_call` (chapter 62) is returned at once: `musttail` when the callee's return type, calling convention, and parameter types match the caller's, and the `tail` hint otherwise. `zero_fill` of `uninit` storage is a memset, `forget` emits nothing, and `rt_atomic_fetch_add`/`rt_atomic_fetch_sub` are acquire-release `atomicrmw` instructions.

## Relationship to the VM

The VM and the LLVM backend are separate implementations of the same storage-form semantics. The codegen stress test compiles each program in `src/testdata/codegen_stress/` with both and checks each tier's result against the file's expected answer (`# expect:`, `# expect-panic:`, or `# expect-text:`). Agreement between the tiers is not the check: they share layout rules, so they can share a mistake and still agree. A file may also bound how many heap blocks `main` allocates on each tier with `# max-allocations:`, which catches storage that should be reused but is allocated afresh, such as a borrow taken in a loop. `# max-live-blocks:` bounds how many heap blocks `main` leaves allocated, counted on every thread once `main` and the tasks it started have finished, which catches storage that is never freed.
