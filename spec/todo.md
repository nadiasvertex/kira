1. Unicode locale-tailored casing (Turkish/Azeri, Lithuanian — needs a locale parameter threaded through every casing call), NFC/NFD normalization, and grapheme-cluster segmentation (UAX #29) so `reversed`/`split` operate on graphemes rather than scalars.
2. "with" style scoped blocks.
3. Store and load binary AST instead of reparsing.
4. Store and load generated bytecode instead of recompiling.
5. `zero`/`one`/`hash` have no impls for the 128-bit types (`int128`, `uint128`, `float128`): a reachable module is compiled in full and the bytecode VM has no representation for them yet, so an `impl zero for int128` in `std.traits` would break every program. They arrive with codegen increment 6.
7. **`shared[T]` is a name with nothing behind it.** Registered as a builtin generic (`src/semantic/types.cpp:51`) and that is the whole implementation: the `shared` expression form produces a plain reference, `shared[T]` has no methods, and no atomic reference count exists. With drops now decided in one place (the ownership checker), this is the rest of [17-shared-ownership-and-drop.md](specification/02-intermediate/17-shared-ownership-and-drop.md).
9. **`just run` silently loses the standard library.** `bazelisk run //src:cinder -- file.cn` runs with the runfiles tree as cwd, where `find_stdlib_source_file` (`src/driver/driver.cpp:185`) finds no candidates, so the stdlib is never injected and `println` fails to lower with a confidently wrong "gap in the compiler" diagnostic. `./bazel-bin/src/cinder file.cn` from the repo root works. Either make the runfiles candidate resolve under `bazel run`, or diagnose a missing stdlib explicitly.
