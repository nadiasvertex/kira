1. Unicode locale-tailored casing (Turkish/Azeri, Lithuanian — needs a locale parameter threaded through every casing call), NFC/NFD normalization, and grapheme-cluster segmentation (UAX #29) so `reversed`/`split` operate on graphemes rather than scalars.
2. "with" style scoped blocks.
3. Store and load binary AST instead of reparsing.
4. Store and load generated bytecode instead of recompiling.
5. `zero`/`one`/`hash` have no impls for the 128-bit types (`int128`, `uint128`, `float128`): a reachable module is compiled in full and the bytecode VM has no representation for them yet, so an `impl zero for int128` in `std.traits` would break every program. They arrive with codegen increment 6.
6. An inline `static for ... => e` in a function body is computed entirely at compile time, so `e` cannot use a runtime value: `static for i in 0..3 => i + n` (with `n` a parameter) is rejected with "`n` is not a compile-time constant that has been evaluated yet", which also has no help line. The spec describes one code path per iteration, which would allow it.
7. An inline `static for` over `T.fields()` in a generic `def` body types its elements as `T` instead of the yielded type. In `def f[T]() -> int32` with `let names = static for f in T.fields() => f.name`, a later `name.len()` on an element fails with "no method `len` on `T`".
8. A `static let` of type `str` cannot be read from run-time code. `static let s = "ab"` with `return s.len() as int32` in `main` fails lowering with "reference to `s` is not a local binding — a bare function value used outside of call position is not supported yet", which misdescribes the problem.
9. Compile-time code cannot call `str.to_uppercase`/`to_lowercase`/`fold_case`/`eq_ignore_case`: `std.unicode` passes its tables as `&TABLE[a..b]`, and the evaluator reports "this unary operator is not yet supported in compile-time evaluation" for `&`. The error points into `std/unicode.cn` with no note naming the user's call site.
10. A compile-time method call on a receiver typed with a type parameter fails. In `static def measure[T](x: T) -> int32 where T: sized` with `return x.size()`, `static let m = measure(box3 { side: 2 })` reports "the receiver has the generic type `T`". An implicit generic call at compile time binds no type arguments at all (`T.name()` in the same body also fails), so the checker cannot tell which impl to use.
11. An unannotated `static let` has no type until its own declaration is checked. Compile-time code checked earlier sees it as unknown, so a method call on it fails: with `lib.cn` declaring `pub static let start = counter { n: 40 }`, a `static def` in `main` returning `lib.start.bumped().get()` reports "the receiver's type is not known". Annotating `start: counter` works around it. `static_binding_type` returns `unknown` for an unannotated binding instead of inferring its initializer on demand.
