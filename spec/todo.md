5. `zero`/`one`/`hash` have no impls for the 128-bit types (`int128`, `uint128`, `float128`), because a reachable module is compiled in full and the bytecode VM has no representation for them yet — an `impl zero for int128` in `std.traits` makes every program fail to compile. They arrive with codegen increment 6, alongside the rest of 128-bit support.
6. Default parameter values are not lowered by either backend — the compiler's own diagnostic ("default parameter values are not lowered by the first milestone") fires the moment a call omits a trailing defaulted argument, even though the checker accepts the declaration and the omitted call alike. Confirmed with `def f(x: int32 = 0) -> int32: x` called as `f()`. `std.test`'s `suite(...)` ([61-std-test.md](specification/04-stdlib/testing/61-std-test.md)) hit this directly and had to drop its documented defaults, requiring every call site to pass all six arguments explicitly until this lands.
7. ~~A bare cross-module function reference used as a plain value (not immediately called) is not reliably lowered outside call position.~~ **Done.** The failure was in lowering, not the checker: `check.cpp`'s `resolve_ident` returned the right *type* for an imported function but recorded nothing about *which* declaration, in which module, it had resolved, so `hir::lower_ident` built an `hir_local_ref` with no `owner_module` and both backends looked the name up under the referencing module's key ("reference to `target` is not a local binding"). `checked_types::resolved_fn_values` now records that resolution for value-position idents — mirroring `resolved_callees` for the call case — and `lower_ident` threads the owning module through, which also lets `find_reachable_modules` see that the declaring module must be compiled. `let g: fn() -> int32 = target` and passing a bare `twice` as an argument both work on the VM and LLVM tiers, via explicit `use inner.target` and wildcard `use inner.*` alike (`test_cross_module_function_used_as_a_value`, `src/cli_test.cpp`). `std.test`'s `--test` discovery still wraps each discovered function in a zero-arg lambda; that is now a free choice rather than a workaround.
