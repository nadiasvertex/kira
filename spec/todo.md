1. Full Unicode case mapping and folding for `std.string` are done (`std.unicode`/`std.unicode_tables`, pure Kira over generated UCD tables — see [52-std-string.md](specification/04-stdlib/strings-and-formatting/52-std-string.md)). Still deferred, each needing more work than "read another generated table": locale-tailored casing (Turkish/Azeri dotted/dotless-I, Lithuanian dot-retention — needs a locale parameter threaded through every casing call), NFC/NFD normalization, and grapheme-cluster segmentation (UAX #29) so `reversed`/`split` can operate on graphemes rather than scalars.
2. "with" style scoped blocks.
3. store and load binary AST instead of reparsing
4. store and load generated bytecode instead of recompiling
5. `zero`/`one`/`hash` have no impls for the 128-bit types (`int128`, `uint128`, `float128`), because a reachable module is compiled in full and the bytecode VM has no representation for them yet — an `impl zero for int128` in `std.traits` makes every program fail to compile. They arrive with codegen increment 6, alongside the rest of 128-bit support.
6. Default parameter values are not lowered by either backend — the compiler's own diagnostic ("default parameter values are not lowered by the first milestone") fires the moment a call omits a trailing defaulted argument, even though the checker accepts the declaration and the omitted call alike. Confirmed with `def f(x: int32 = 0) -> int32: x` called as `f()`. `std.test`'s `suite(...)` ([61-std-test.md](specification/04-stdlib/testing/61-std-test.md)) hit this directly and had to drop its documented defaults, requiring every call site to pass all six arguments explicitly until this lands.
7. A bare cross-module function reference used as a plain value (not immediately called) is not reliably lowered outside call position — confirmed with `use inner.target` then `let g: fn() -> int32 = target` (or passed as a call argument), both failing with "no concrete checked type is available for this node" even though the identical construct works for a *same-module* function reference or a lambda literal. `check.cpp`'s `resolve_ident` (the general value-position ident resolver) never calls `record_expr_type` in its `module_->functions`/`find_import`/wildcard-import branches, unlike `infer_call`'s ident-*callee* ladder, which does. `std.test`'s `--test` discovery ([61-std-test.md](specification/04-stdlib/testing/61-std-test.md)) sidesteps this by always wrapping a discovered function in a zero-arg lambda (`() => module.tests.func()`) rather than passing it as a bare value.
