1. Unicode locale-tailored casing (Turkish/Azeri, Lithuanian — needs a locale parameter threaded through every casing call), NFC/NFD normalization, and grapheme-cluster segmentation (UAX #29) so `reversed`/`split` operate on graphemes rather than scalars.
2. "with" style scoped blocks.
3. Store and load binary AST instead of reparsing.
4. Store and load generated bytecode instead of recompiling.
5. `zero`/`one`/`hash` have no impls for the 128-bit types (`int128`, `uint128`, `float128`): a reachable module is compiled in full and the bytecode VM has no representation for them yet, so an `impl zero for int128` in `std.traits` would break every program. They arrive with codegen increment 6.
6. The drop decisions are split between the ownership checker (`src/semantic/ownership_cfg.cpp`) and the lowerer (`src/hir/lower.cpp`, `drop_schedule.cpp`), which agree only through shared helper functions. Unify them into one decision. (`needs_drop[T]()` is done.)

   Plan: the ownership side produces one drop record per body (`elaborate_drops`), keyed by declaring AST node, and the lowerer only emits what it lists. The record covers owned locals, drop sites (scope exits, assignments, leftover pattern parts, unmatched subjects, jumps, generator cancel points), flag set/clear sites, and per-node facts (binding ownership, `consumes_receiver`, loop iterator handle type). The ownership predicates (`owns_pattern_bindings`, `arm_owns_subject`, `owning_alias`, `for_variable_owns`, `clause_variable_owns`, `loop_handle_type`) become file-local so the lowerer cannot ask them. Steps, each landed separately with all tests green:
   1. Add the record and a temporary consistency mode: the lowerer computes its own answer for each decision and fails on any difference from the record. Landed as `drop_schedule::owned_locals` plus `lowerer::check_drop_agreement`, enabled by `KIRA_CHECK_DROP_AGREEMENT=1` (`bazelisk test //... --test_env=KIRA_CHECK_DROP_AGREEMENT=1`). It compares the multiset of owned droppable locals. First finding: a lambda parameter whose type is inferred (`l => l.into_iter()` in `std_test/iter_adapters_nesting.cn`) is owned by the lowerer, which reads its type from the lambda's `fn` type, but unknown to the CFG, which reads the pattern's node type, so the CFG never schedules a drop for it. Fix in step 2 or 3 by giving the CFG the lambda's `fn` parameter types.
   2. Identify locals by declaring node instead of name plus `shadow_depth`. Done: `pending_drop::node` replaces `shadow_depth`, `lowerer::declare_local` takes the declaring node, and the agreement check now compares nodes too. The CFG now reads an inferred lambda parameter's type from the lambda's `fn` type, which closes the step 1 finding.
   3. Pattern binding ownership comes from the record. Done: `drop_schedule::owned_bindings`, `owning_patterns` and `owning_subjects` (filled from `function_cfg`) replace the lowerer's calls to `owns_pattern_bindings`, `arm_owns_subject` and `owning_alias` for `let`, `if let`, `while let`, `match` arms and destructuring parameters. The `for` and comprehension destructuring sites still call `for_variable_owns` (step 5).
   4. Move the lowerer-only drops (`_` leftovers, `..` skipped fields, unmatched subject of `let else`/`if let`/`match`) into CFG events so move tracking and drop flags cover them. Done as records, not events: `function_cfg::leftover_drops` (the `_` and `..` nodes) and `unmatched_drops` (the top-level pattern of a `let else`/`if let`/`while let` whose miss path owns the subject), read through `drop_schedule`. The lowerer checks its old answer against them under `KIRA_CHECK_DROP_AGREEMENT`. These drops sit on a path where the subject was just consumed, so no move state or flag can change them; an event would add no information. `match` has no unmatched-subject drop.
   5. Loop variable ownership, iterator handle type, and `consumes_receiver` come from the record. Done: `function_cfg::owning_loops` (keyed by the `for_stmt` or comprehension clause), `loop_handles` (keyed by the loop's `iterable` member) and `consuming_calls` (the `into_iter` calls) reach the lowerer through `drop_schedule`, with the old answers still checked under `KIRA_CHECK_DROP_AGREEMENT`. The handle's type is still taken from the lowerer's dispatch; the agreement check on `owned_locals` compares it. The synthesized adapter call in `lower_iterator_loop` still sets `consumes_receiver = true` itself, since it has no AST call.
   6. Temporaries: the CFG records each temporary's end point and `make_references_explicit` reads it. Done: each temporary frame of the CFG is keyed by its AST node (a statement, or a full expression: an `if`/`while` condition, a match or loop guard, the right operand of `and`/`or`, a returned or yielded value, a block's value, a `while let` subject). Every temporary is a CFG local: a value borrowed while not a place, the object a field is read from or indexed, and a value computed and discarded. `function_cfg::temporary_ends` maps the expression each one holds to the frame it ends with (`drop_schedule::temporary_ends`). HIR nodes carry `hir_node::origin`, the AST node they were lowered from, and the rewriter puts each temporary in the frame the record names. A node lowering synthesized has no origin and keeps the innermost frame; so does the receiver a call consumes. Before this step the CFG ended a condition's or guard's temporaries with the statement, later than the rewriter dropped them. Under `KIRA_CHECK_DROP_AGREEMENT` the rewriter reports a temporary with no record, a record naming no open frame, and a record naming an outer frame than the one it would have used.
   7. Delete the old path and the consistency mode.
7. **`shared[T]` is a name with nothing behind it.** Registered as a builtin generic (`src/semantic/types.cpp:51`) and that is the whole implementation: the `shared` expression form produces a plain reference, `shared[T]` has no methods, and no atomic reference count exists. Paired with item 6, this is the other half of [17-shared-ownership-and-drop.md](specification/02-intermediate/17-shared-ownership-and-drop.md).
9. **`just run` silently loses the standard library.** `bazelisk run //src:cinder -- file.cn` runs with the runfiles tree as cwd, where `find_stdlib_source_file` (`src/driver/driver.cpp:185`) finds no candidates, so the stdlib is never injected and `println` fails to lower with a confidently wrong "gap in the compiler" diagnostic. `./bazel-bin/src/cinder file.cn` from the repo root works. Either make the runfiles candidate resolve under `bazel run`, or diagnose a missing stdlib explicitly.
10. **The compile-time evaluator has no loops.** `while` and `for` inside a function evaluated at compile time (e.g. `static X: int64 = fib(50)` where `fib` loops) fall to the `default` case of `evaluate_stmt` in `src/comptime/eval.cpp` ("this statement form is not yet supported in compile-time evaluation"). [31-compile-time-execution.md](specification/03-advanced/31-compile-time-execution.md) promises "the same functions, loops, and pattern matching"; recursion works today, loops don't. The failure also cascades: the bytecode stage then reports `` reference to `X` is not a local binding — a bare function value used outside of call position is not supported yet `` for the scalar `static`, the same confidently wrong message as item 11. A failed `static` initializer should stop lowering from ever seeing the binding.
11. **`bool + bool` is not diagnosed.** `let a = true; let s = a + a` type-checks and then fails in lowering with "no concrete checked type is available for this node" — a confidently wrong "gap in the compiler" for a user mistake. `require_operand_trait` on a builtin with no operator impl answers `unknown` silently instead of "operator `+` requires numeric operands, found `bool`". The deferred check for an operand that settles later (`defer_open_arithmetic`) inherits the same silence.
13. **A generic body calling an implicit generic does not lower.** `def quad[T](v: T) -> T where T: add: return twice(twice(v))` with `def twice(x): x + x` type-checks and then fails in lowering ("no concrete checked type is available"). The template skips an implicit generic's call whose argument is written in its parameters (`passes_template_param`: no `pending_open_param_call` is queued), and an instance made by substitution has no walk to queue one. Needs a template elaboration that queues the call per instance with the substituted argument types, and a way for the result type to flow on. Predates phase 9.7.
15. **UFCS on a literal receiver ignores the parameter's type.** `4.id64()` for `def id64(x: int64) -> int64` reports `` `id64` cannot be called on `int32` ``: the receiver literal is defaulted before the parameter it is passed to is read. `id64(4)` works.
16. **A list literal passed straight to a generic parameter does not solve it.** `first([5, 6])` for `def first[T](xs: list[T]) -> T` reports `` cannot tell what `T` is in this call to `first` ``. `let xs = [5, 6]; first(xs)` works. Predates 2026-09-28.
17. **A `match` guard cannot see the arm's pattern bindings.** `match o: @some(x) if x > 0 => x` fails in lowering with "reference to `x` is not a local binding": `lower_match` lowers the guard before the bindings' `hir_let`s, which are spliced into the arm body after it. Predates 2026-09-29.
19. **A nested list literal does not lower.** `let xs = [[1], [2]]` type-checks and then fails with "could not lower module `std.list`" at `list[T]::new` (`src/std/list.cn:40`, "no concrete checked type is available for this node" on `alloc[T](0)`): the `list[list[int32]]` instance of `new` is lowered without its types. `let xs: list[list[int32]] = [[1], [2]]` was not tried. Found 2026-09-29.
21. **`eq`/`ord` take their right operand by value, but comparison operators only read it.** `impl ord for t: def cmp(self, other: t)` drops `other` at the end of `cmp` when `t` needs a drop, while `a < b` leaves `b` with its owner, which drops it again. Latent until a droppable type implements `eq` or `ord`. Found 2026-09-30.
22. **A `match` whose first arm is a jump has type `never`.** `let v = match k: 1 => break` followed by `n => n` types `v` as `never` instead of `int32`, so `println("{v}")` reports "`never` does not support the requested formatting". Annotating `let v: int32` works. The arms' type is taken from the first arm instead of joining all of them with `never` as the bottom. Found 2026-10-01.
