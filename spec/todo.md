1. Full Unicode case mapping and folding for `std.string` are done (pure Kira over generated UCD tables — see [52-std-string.md](specification/04-stdlib/strings-and-formatting/52-std-string.md)). Still deferred: locale-tailored casing (Turkish/Azeri, Lithuanian — needs a locale parameter threaded through every casing call), NFC/NFD normalization, and grapheme-cluster segmentation (UAX #29) so `reversed`/`split` operate on graphemes rather than scalars.
2. "with" style scoped blocks.
3. Store and load binary AST instead of reparsing.
4. Store and load generated bytecode instead of recompiling.
5. `zero`/`one`/`hash` have no impls for the 128-bit types (`int128`, `uint128`, `float128`): a reachable module is compiled in full and the bytecode VM has no representation for them yet, so an `impl zero for int128` in `std.traits` would break every program. They arrive with codegen increment 6.
6. **Scope-exit `drop`: done for the common case, with deliberate gaps.** `checker::resolve_drop_plans` (`src/semantic/check.cpp`) and `hir::compute_drop_schedule` (`src/hir/drop_schedule.{h,cpp}`) schedule reverse-declaration-order drop calls at scope exit and at `return`/`break`/`continue`; `hir::lowerer` synthesizes the `hir_call`s — an ordinary function call, so no new backend code. Verified on both backends: `src/testdata/std_test/scope_exit_drop.kira`; direct `x.drop()` is rejected (`src/testdata/semantic_check_test/reject_direct_drop_call.kira`). `compute_drop_schedule` is a second walker alongside `move_check` (not a replacement).
   Remaining gaps, each left deliberately:
   - A block/function whose tail is a non-`unit` value skips scope-exit drop for that scope entirely (a leak, never a double-drop) — needs a temporary-materialization pass.
   - Locals a `return expr` merely borrows from are never dropped (the read happens as part of compiling the return); a local `return`ed directly is unaffected.
   - Match-arm, `for`-loop, and destructuring pattern bindings are not tracked — only plain `let`/`var` and simple parameters are; the current `for`-loop desugaring routes its loop variable through exactly this untracked path.
   - Sum-type field-wise drop is not implemented; only the sum's own `impl drop` runs.
   - Unwinding through drops on panic is moot: there is no stack unwinding (`panic`/`assert` compile to a trap).
   - No prelude `drop(x)` free function exists: bare `drop(x)` is accepted by the checker, then fails in lowering with a confidently wrong "no concrete checked type" diagnostic for what is really an unresolved name.
   `spec/list-migration-design.md`'s phase 4 needs only reverse-order drop, moved-from exclusion, and struct field-wise drop from this item — all three hold for the common case it will exercise.
7. **`shared[T]` is a name with nothing behind it.** Registered as a builtin generic (`src/semantic/types.cpp:51`) and that is the whole implementation: the `shared` expression form produces a plain reference, `shared[T]` has no methods, and no atomic reference count exists. Paired with item 6, this is the other half of [17-shared-ownership-and-drop.md](specification/02-intermediate/17-shared-ownership-and-drop.md).
8. **`scope:` blocks do not parse.** `scope_stmt = "scope" ":" block` is in [kira-grammar.ebnf](kira-grammar.ebnf) line 524 and is the drop chapter's normative way to end a binding's lifetime early, but there is no `kw_scope` token or parser support. Related to item 2 but distinct: this is the bare lexical scope, not a `with`-style context manager.
9. **`just run` silently loses the standard library.** `bazelisk run //src:kira -- file.kira` runs with the runfiles tree as cwd, where `find_stdlib_source_file` (`src/driver/driver.cpp:185`) finds no candidates, so the stdlib is never injected and `println` fails to lower with a confidently wrong "gap in the compiler" diagnostic. `./bazel-bin/src/kira file.kira` from the repo root works. Either make the runfiles candidate resolve under `bazel run`, or diagnose a missing stdlib explicitly.
10. **Dotted names: done.** Semantics in [Visible Modules / Dotted Names](specification/01-core/12-modules-and-imports.md#visible-modules). The checker is the single place that decides whether `a.b` is field access or a module path (`checker::dotted_root_is_value`: a local, including a `static for` binder, always wins) and records value paths in `checked_types::value_path_types`, which is all `hir::lower_module_path` reads (so `a.b.c` chains on a local now lower too). Module-rooted paths are validated from the checker via `validate_module_reference`; `resolution.cpp` no longer validates expression paths without scope information. Absolute paths reach only the module's own root, `std`, or an import (`root_visible_without_import`, shared by validation and the checker's lookups); `--test`'s runner imports each suite's anchor module. `validate_value_module_conflicts` rejects a `def`/`static` named like a declared child or imported module. Regression guards: `cli_test`'s `test_stdlib_immune_to_user_root_module_names` (a user root module for every dotted-name root in `src/std/`), `test_local_binding_shadows_same_named_module`, and `check_test`'s visibility/conflict fixtures. Left open:
    - A top-level `type` named like a visible module is not rejected (rule 2 covers values only).
    - `use a as b` (renaming a root module) is not a `use` form.
    - `comptime::evaluator::eval_module_path` and `comptime/hygiene.cpp` still read a path's root as a value on their own; the comptime evaluator has no module values, so this cannot misread a module path today, but it is a second reading.
    - The session scope tree (`session.cpp` `walk_node`) does not descend into most expressions and has no `static for` binder scope; nothing depends on it for dotted names any more, but its `default:` still hides missing binders.
11. **`std.platform`'s assembled source races between concurrent compiles.** `driver.cpp` truncates and rewrites a fixed `$TMPDIR/kira-platform.kira` on every compile; the comment says identical content makes this race-free, but a reader can observe the truncated file mid-write. Seen as a spurious ``expected `:` `` parse error in `pub def uname() -> platform_info` when `bazelisk test //...` ran `cli_test` alongside other compiling tests. Write to a unique temp file and rename into place, or keep the assembled source in memory.
