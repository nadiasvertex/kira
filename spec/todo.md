1. Full Unicode case mapping and folding for `std.string` are done (pure Cinder over generated UCD tables — see [52-std-string.md](specification/04-stdlib/strings-and-formatting/52-std-string.md)). Still deferred: locale-tailored casing (Turkish/Azeri, Lithuanian — needs a locale parameter threaded through every casing call), NFC/NFD normalization, and grapheme-cluster segmentation (UAX #29) so `reversed`/`split` operate on graphemes rather than scalars.
2. "with" style scoped blocks.
3. Store and load binary AST instead of reparsing.
4. Store and load generated bytecode instead of recompiling.
5. `zero`/`one`/`hash` have no impls for the 128-bit types (`int128`, `uint128`, `float128`): a reachable module is compiled in full and the bytecode VM has no representation for them yet, so an `impl zero for int128` in `std.traits` would break every program. They arrive with codegen increment 6.
6. **Scope-exit `drop`: done for the common case, with deliberate gaps.** `checker::resolve_drop_plans` (`src/semantic/check.cpp`) and `hir::compute_drop_schedule` (`src/hir/drop_schedule.{h,cpp}`) schedule reverse-declaration-order drop calls at scope exit and at `return`/`break`/`continue`; `hir::lowerer` synthesizes the `hir_call`s — an ordinary function call, so no new backend code. Verified on both backends: `src/testdata/std_test/scope_exit_drop.cn`; direct `x.drop()` is rejected (`src/testdata/semantic_check_test/reject_direct_drop_call.cn`). `compute_drop_schedule` is a second walker alongside `move_check` (not a replacement).
   Remaining gaps, each left deliberately:
   - A block/function whose tail is a non-`unit` value skips scope-exit drop for that scope entirely (a leak, never a double-drop) — needs a temporary-materialization pass.
   - Locals a `return expr` merely borrows from are never dropped (the read happens as part of compiling the return); a local `return`ed directly is unaffected.
   - Match-arm, `for`-loop, and destructuring pattern bindings are not tracked — only plain `let`/`var` and simple parameters are; the current `for`-loop desugaring routes its loop variable through exactly this untracked path.
   - Sum-type field-wise drop is not implemented; only the sum's own `impl drop` runs.
   - Unwinding through drops on panic is moot: there is no stack unwinding (`panic`/`assert` compile to a trap).
   - No prelude `drop(x)` free function exists: bare `drop(x)` is accepted by the checker, then fails in lowering with a confidently wrong "no concrete checked type" diagnostic for what is really an unresolved name.
   `spec/list-migration-design.md`'s phase 4 needs only reverse-order drop, moved-from exclusion, and struct field-wise drop from this item — all three hold for the common case it will exercise.
7. **`shared[T]` is a name with nothing behind it.** Registered as a builtin generic (`src/semantic/types.cpp:51`) and that is the whole implementation: the `shared` expression form produces a plain reference, `shared[T]` has no methods, and no atomic reference count exists. Paired with item 6, this is the other half of [17-shared-ownership-and-drop.md](specification/02-intermediate/17-shared-ownership-and-drop.md).
8. **`scope:` blocks do not parse.** `scope_stmt = "scope" ":" block` is in [kira-grammar.ebnf](kira-grammar.ebnf) line 524 and is the drop chapter's normative way to end a binding's lifetime early, but there is no `kw_scope` token or parser support. Related to item 2 but distinct: this is the bare lexical scope, not a `with`-style context manager.
9. **`just run` silently loses the standard library.** `bazelisk run //src:kira -- file.cn` runs with the runfiles tree as cwd, where `find_stdlib_source_file` (`src/driver/driver.cpp:185`) finds no candidates, so the stdlib is never injected and `println` fails to lower with a confidently wrong "gap in the compiler" diagnostic. `./bazel-bin/src/kira file.cn` from the repo root works. Either make the runfiles candidate resolve under `bazel run`, or diagnose a missing stdlib explicitly.
10. **Dotted names: done.** Semantics in [Visible Modules / Dotted Names](specification/01-core/12-modules-and-imports.md#visible-modules). One rule, `checker::classify_dotted_root` (`src/semantic/check.cpp`): a lexical local wins; the module's own root and `std` are modules; a module-level `def`/`static` (declared or imported) is a value (`origin.x`, lowered by folding a scalar field to a constant); anything else is a module path, which may run into a `static`'s fields (`geo.origin.x`). The compile-time evaluator no longer reads paths itself: it asks the checker (`evaluator::set_path_resolver`), passing only whether the root is one of its own frame locals, and module-level statics it reaches that way are evaluated per declaration in their declaring module (`ensure_static_binding_evaluated`'s `owner`). `comptime/hygiene.cpp` makes no module-vs-value decision (it renames a fragment's own binding, which rule 1 already makes win). Rule 2 is general (`validate_module_name_conflicts`): any declaration or imported name (wildcards included) clashing with a declared child or imported module, and two imports binding one name when either is a module; an import no longer silently wins over a same-named inline submodule. `use a as b` renames a root module. The session scope tree (`session.cpp` `walk_node`) reaches every node kind, with no `default:`, and gives `static for` binders their own scope. Regression guards: `cli_test`'s `test_dotted_names_through_module_values_and_root_alias` (both backends, by value), `check_test`'s `test_module_name_conflicts_are_general`/`test_root_module_alias`/`test_dotted_name_rooted_at_module_value`, `resolution_test`'s `test_scope_walk_reaches_nested_expressions_and_static_for`, `parser_test`'s `root_module_alias`. Bare names in compile-time code go through the checker too (`evaluator::set_name_resolver` → `checker::read_bare_name_for_comptime`, the same module-scope lookup `resolve_ident` uses), and a compile-time call runs in the callee's declaring module (`evaluator::set_call_context` → `checker::in_module_context`; a monomorphized instance runs in its template's), so a parent and a submodule that each declare `static limit`/`static def f` no longer collide. A `static def` body sees only its own frames, never its caller's locals, and module-qualified compile-time calls (`inner.f(2)`) work. The evaluator's flat tables remain only for a standalone evaluator and for `evaluate_derive_call`'s by-name `derive_<trait>` lookup. Regression guard: `cli_test`'s `test_comptime_bare_names_resolve_per_module` (both backends, by value).
11. **A struct-valued `static` has no runtime storage.** `static let origin: point = ...` is usable at compile time and its scalar fields fold to constants (`origin.x`), but `let p = origin` or `origin.a` (a struct field) fails in lowering — the bytecode compiler's message ("a bare function value used outside of call position is not supported yet") is confidently wrong. Only arrays/lists of scalars are reified as globals (`reify_static_global`).
12. **A user type named like a prelude type loses to it in type position.** `type box = { w: int32 }` then `let b: box = box { w: 1 }` reports ``type mismatch: expected `box`, found `box` `` — the annotation resolves to the prelude's builtin `box`, the struct literal to the user's type. A module's own declaration should shadow the prelude, as it does for values.
