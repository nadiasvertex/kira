5. `zero`/`one`/`hash` have no impls for the 128-bit types (`int128`, `uint128`, `float128`), because a reachable module is compiled in full and the bytecode VM has no representation for them yet — an `impl zero for int128` in `std.traits` makes every program fail to compile. They arrive with codegen increment 6, alongside the rest of 128-bit support.
6. `deriving hash`  does not lower through the HIR/LLVM tier at all yet — `a.hash()` on any `deriving hash` type fails HIR lowering with "no concrete checked type is available for this node" — so this fix, like the rest of `deriving hash`, is exercised only via the tier-0 bytecode VM (`cli_test.cpp`'s `run` mode), not `codegen_stress_test`.
7. static for's inline (=>) form has a checker bug. The exact spec example (static for field in T.fields() => field.name as a function's sole body) is rejected with "not every path... returns a value" — the return-coverage checker doesn't recognize the inline form as producing a value.
8. Module-scope static if selecting between top-level items doesn't register the winning branch's name into scope. static if true: type word = int64 else: type word = int32 type-checks, but any later word usage fails "undefined type word" — the item never gets registered by name resolution.
