1. Unicode locale-tailored casing (Turkish/Azeri, Lithuanian — needs a locale parameter threaded through every casing call), NFC/NFD normalization, and grapheme-cluster segmentation (UAX #29) so `reversed`/`split` operate on graphemes rather than scalars.
2. "with" style scoped blocks.
3. Store and load binary AST instead of reparsing.
4. Store and load generated bytecode instead of recompiling.
5. `float128` has no representation on either backend, so it has no `zero`/`one`/`hash`/scalar trait impls and no `std.limits` answers. A reachable module is compiled in full, so an impl naming it would break every program. It needs a soft-float implementation: LLVM's `fp128` lowers to compiler-rt/libgcc calls, and Apple arm64 has no `fp128` support at all, so the runtime has to supply the arithmetic itself.
6. `std.limits.min[int64]()` (and `min[int128]()`, `min[int32]()`, ...) fails at compile time with "an integer overflowed its type". The body `-9223372036854775808 as T` is evaluated as `-(9223372036854775808 as T)`, so the cast overflows before the negation. The diagnostic's primary label also points at the wrong file: it shows a line of `limits.cn` with the caller's span.
7. A call to a `static pure def` from `std.limits` in ordinary run-time code fails at code generation: `let a = min[int64]()` in `main` reports "call to `min$int64` could not be resolved to a function in this compiled module". Binding it to a `static let` first works.
8. A module-qualified call with explicit type arguments does not bind them: `use std.limits` then `limits.max[int32]()` reports "cannot tell what `T` is in this call to `max`". `use std.limits.max` then `max[int32]()` works.
9. A trait's static method called directly on a builtin type fails at code generation: `int64.zero()` (with `use std.traits.zero`) reports "no concrete checked type is available for this node". The same call through a bound (`T.zero()` with `T: zero`) works.
10. On Linux x86-64, `int128` checked multiplication may lower to a call to `__muloti4`, which libgcc does not provide. Untested; macOS links it from compiler-rt.
11. A compound assignment through a dereference, `*p += x` with `p: &mut int32`, is not supported on either backend. `*p = *p + x` works. This also blocks the next item.
12. There is no mutable deref trait, so `*guard += 1` on a `mutex_guard` (chapter 30's example) cannot compile. `std.sync` guards offer `get_mut()` and `set(value)` instead.
13. A bare `on(ctx, t)` or `on(ctx): body` value that is dropped without being awaited leaks what its inner task captured: the wrapper's drop does not drop the inner task's captures.
14. `implements[T, copy]` cannot be used, because `copy` is a concept rather than a trait. A method that needs "copy if possible, else clone" has to be split in two, as `watch_reader.get` and `watch_reader.cloned` are.
15. `await yield` parses and checks but is not lowered on either backend.
