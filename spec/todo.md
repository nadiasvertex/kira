1. Unicode locale-tailored casing (Turkish/Azeri, Lithuanian — needs a locale parameter threaded through every casing call), NFC/NFD normalization, and grapheme-cluster segmentation (UAX #29) so `reversed`/`split` operate on graphemes rather than scalars.
2. "with" style scoped blocks.
3. Store and load binary AST instead of reparsing.
4. Store and load generated bytecode instead of recompiling.
5. `zero`/`one`/`hash` have no impls for the 128-bit types (`int128`, `uint128`, `float128`): a reachable module is compiled in full and the bytecode VM has no representation for them yet, so an `impl zero for int128` in `std.traits` would break every program. They arrive with codegen increment 6.
6. **Scope-exit `drop`: done for the common case, with deliberate gaps.** `checker::resolve_drop_plans` (`src/semantic/check.cpp`) and `hir::compute_drop_schedule` (`src/hir/drop_schedule.{h,cpp}`) schedule reverse-declaration-order drop calls at scope exit and at `return`/`break`/`continue`; `hir::lowerer` synthesizes the `hir_call`s — an ordinary function call, so no new backend code. Verified on both backends: `src/testdata/std_test/scope_exit_drop.cn`; direct `x.drop()` is rejected (`src/testdata/semantic_check_test/reject_direct_drop_call.cn`). `compute_drop_schedule` reads what is still owned at each exit from the ownership checker's CFG and "maybe moved" pass (`semantic::ownership::owned_at_scope_exits`), so a value only lent to a `&`/`&mut` parameter is dropped and one moved on any path is not.
   Remaining gaps, each left deliberately:
   - A block/function whose tail is a non-`unit` value skips scope-exit drop for that scope entirely (a leak, never a double-drop) — needs a temporary-materialization pass.
   - Locals a `return expr` merely borrows from are never dropped (the read happens as part of compiling the return); a local `return`ed directly is unaffected.
   - Match-arm, `for`-loop, and destructuring pattern bindings are not dropped — only plain `let`/`var` and single-name parameters are. The ownership CFG sees them, but a pattern binding can alias part of a subject that was not moved (`match self.f: some(v) => ...`; partial moves are not tracked), so dropping it could double-drop. Needs partial-move tracking first; the current `for`-loop desugaring routes its loop variable through this path.
   - A name shadowed within the scopes one exit closes (`let a = ...; let a = ...`) leaks its outer binding: `lowerer` finds drops by name, which reaches only the innermost.
   - Sum-type field-wise drop is not implemented; only the sum's own `impl drop` runs.
   - Unwinding through drops on panic is moot: there is no stack unwinding (`panic`/`assert` compile to a trap).
   - No prelude `drop(x)` free function exists: bare `drop(x)` is accepted by the checker, then fails in lowering with a confidently wrong "no concrete checked type" diagnostic for what is really an unresolved name.
7. **`shared[T]` is a name with nothing behind it.** Registered as a builtin generic (`src/semantic/types.cpp:51`) and that is the whole implementation: the `shared` expression form produces a plain reference, `shared[T]` has no methods, and no atomic reference count exists. Paired with item 6, this is the other half of [17-shared-ownership-and-drop.md](specification/02-intermediate/17-shared-ownership-and-drop.md).
8. **`scope:` blocks do not parse.** `scope_stmt = "scope" ":" block` is in [cinder-grammar.ebnf](cinder-grammar.ebnf) line 524 and is the drop chapter's normative way to end a binding's lifetime early, but there is no `kw_scope` token or parser support. Related to item 2 but distinct: this is the bare lexical scope, not a `with`-style context manager.
9. **`just run` silently loses the standard library.** `bazelisk run //src:cinder -- file.cn` runs with the runfiles tree as cwd, where `find_stdlib_source_file` (`src/driver/driver.cpp:185`) finds no candidates, so the stdlib is never injected and `println` fails to lower with a confidently wrong "gap in the compiler" diagnostic. `./bazel-bin/src/cinder file.cn` from the repo root works. Either make the runfiles candidate resolve under `bazel run`, or diagnose a missing stdlib explicitly.
12. **The compile-time evaluator has no loops.** `while` and `for` inside a function evaluated at compile time (e.g. `static X: int64 = fib(50)` where `fib` loops) fall to the `default` case of `evaluate_stmt` in `src/comptime/eval.cpp` ("this statement form is not yet supported in compile-time evaluation"). [31-compile-time-execution.md](specification/03-advanced/31-compile-time-execution.md) promises "the same functions, loops, and pattern matching"; recursion works today, loops don't. The failure also cascades: the bytecode stage then reports `` reference to `X` is not a local binding — a bare function value used outside of call position is not supported yet `` for the scalar `static`, the same confidently wrong message as item 11. A failed `static` initializer should stop lowering from ever seeing the binding.
14. **The result of an implicit generic is not typed by a later use.** For `def add_one(x): x + 1`, `let r = add_one(5)` then `let c: int64 = r` reports `` expected `int64`, found `int32` ``: the instance for the `5` is chosen before the annotation is read. `let a = 5; let c: int64 = a` works, so this is the implicit-generic call path choosing early, not literal defaulting. Found while making literals wait for their demand points.
15. **`bool + bool` is not diagnosed.** `let a = true; let s = a + a` type-checks and then fails in lowering with "no concrete checked type is available for this node" — a confidently wrong "gap in the compiler" for a user mistake. `require_operand_trait` on a builtin with no operator impl answers `unknown` silently instead of "operator `+` requires numeric operands, found `bool`". The deferred check for an operand that settles later (`defer_open_arithmetic`) inherits the same silence.
16. std.algo's filter passes a T by value to pred and then returns it. For a non-copyable T that's a double move. The move checker still doesn't track T, which is why nothing reports it.
17. **A generic body calling an implicit generic does not lower.** `def quad[T](v: T) -> T where T: add: return twice(twice(v))` with `def twice(x): x + x` type-checks and then fails in lowering ("no concrete checked type is available"). The template skips an implicit generic's call whose argument is written in its parameters (`passes_template_param`: no `pending_open_param_call` is queued), and an instance made by substitution has no walk to queue one. Needs a template elaboration that queues the call per instance with the substituted argument types, and a way for the result type to flow on. Predates phase 9.7.
19. **Implicit generics (unannotated parameters) have deliberate gaps.** A *method* in an `impl`/`extend` block with an unannotated parameter resolves to its template rather than an instance; an unannotated *return* type is inferred only for free functions and implicit-generic instances; an implicit generic that is never called is never checked for errors; and no trait bounds are inferred for an open parameter — each instance is simply checked per type. Also a hazard: the end-of-body default that settles an inferred return type runs the leaf queue, which can default a caller's pending literal before a later statement would have pinned it.
