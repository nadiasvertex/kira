5. `zero`/`one`/`hash` have no impls for the 128-bit types (`int128`, `uint128`, `float128`), because a reachable module is compiled in full and the bytecode VM has no representation for them yet — an `impl zero for int128` in `std.traits` makes every program fail to compile. They arrive with codegen increment 6, alongside the rest of 128-bit support.
6. Default parameter values are lowered on both backends (done). An omitted argument is filled in at the *call site*, by lowering the callee's default expression there (`hir::lower_call`); the callee stays an ordinary function of full declared arity and knows nothing about defaults, so no calling convention changed. The mapping the checker already built (`call_argument_mapping`) carries the default expressions and parameter names across for it. `std.test`'s `suite(...)` has its documented hook defaults back, and the synthesized `--test` runner now names only the hooks a suite actually declares. Remaining restriction: a default that refers to *another parameter* of the same function (`def f(a: int32, b: int32 = a)`) is refused at lowering — its value belongs to a call frame that does not exist yet at the call site. Lifting it would mean compiling each such default into a thunk in the callee's own module and calling it with the already-evaluated arguments; nothing in the pipeline needs that yet.
